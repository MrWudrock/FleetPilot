## 1. Обзор

### Что такое FleetPilot

FleetPilot — B2B SaaS-платформа с ИИ-агентами, которая автоматизирует ключевые процессы транспортной компании **поверх уже установленных систем** (GPS, TMS).

### Ключевые преимущества

- **Не заменяет** существующие GPS/TMS системы
- **Подключается** к Omnicomm, СтавТРЭК, Master TMS через API
- **Автоматизирует** 4 процесса ИИ-агентами
- **Окупаемость** за 7–10 месяцев

### ИИ-агенты

| Агент | Функция | Эффект |
|-------|---------|--------|
| **Route Agent** | Оптимизация маршрутов | −10–18% расход топлива |
| **Dispatch Agent** | Автоматизация диспетчеризации | −86% время обработки заявок |
| **Fuel Agent** | Контроль топлива | −10–26% расход топлива |
| **Maintenance Agent** | Предиктивное ТО | −15% незапланированные простои |

### Целевой ICP

- Автопарк: 20–50 единиц техники
- Бюджет: ₽10–15M/год
- Уже есть GPS (Omnicomm / СтавТРЭК)
- Маршруты: региональные и межрегиональные

## 2. Подготовка к внедрению

### 2.1 Требования к инфраструктуре

| Компонент | Требование |
|-----------|------------|
| **Интернет** | Стабильный, ≥ 10 Мбит/с |
| **Браузер** | Chrome 90+, Firefox 90+, Edge 90+ |
| **GPS-система** | Omnicomm, СтавТРЭК или MSS GLONASS |
| **API доступ** | Ключи API от GPS-провайдеров |
| **Email** | Рабочий email для уведомлений |

### 2.2 Необходимые данные

Перед началом внедрения подготовьте:

#### От GPS-провайдера

- [ ] API ключ Omnicomm / СтавТРЭК
- [ ] Список ТС с госномерами и ID в системе
- [ ] Список водителей с привязкой к ТС
- [ ] Исторические данные за 3 месяцы (если доступны)

#### От руководства

- [ ] Операционный бюджет/год
- [ ] Текущие расходы на топливо/мес
- [ ] Количество заявок/день
- [ ] Среднее время обработки заявки
- [ ] Текущий процент незапланированных простоев

#### IT-отдел

- [ ] Доступ к DNS-записям домена
- [ ] Доступ к email-серверу (если нужен свой SMTP)
- [ ] Список пользователей с ролями

### 2.3 Роли в проекте

| Роль | Ответственность | Лицо |
|------|-----------------|------|
| **Руководитель проекта** | Общее управление, принятие решений | Коммерческий директор |
| **Технический лидер** | Интеграция, настройка API | IT-отдел / системный администратор |
| **Champion** | Ежедневное использование, обратная связь | Главный диспетчер |
| **Пользователи** | Тестирование, обучение | Диспетчеры, механики |

## 3. Этап 1: Интеграция GPS (недели 1–4)

### 3.1 Подключение Omnicomm

#### Шаг 1: Получение API ключа

1. Войдите в [Omnicomm Online](https://online.omnicomm.ru)
2. Перейдите в **Настройки** → **API**
3. Создайте новый API ключ
4. Скопируйте ключ и сохраните в безопасном месте

#### Шаг 2: Настройка в FleetPilot

1. Войдите в FleetPilot → **Интеграции**
2. Нажмите **+ Добавить коннектор**
3. Выберите **Omnicomm Online**
4. Введите:
   - API URL: `https://online.omnicomm.ru/api/v2`
   - API ключ: [ваш ключ]
5. Нажмите **Подключить**

#### Шаг 3: Маппинг ТС

FleetPilot автоматически загрузит список ТС из Omnicomm. Убедитесь, что:

- [ ] Все ТС отображаются в списке
- [ ] Госномеры корректны
- [ ] Привязка к водителям верна

Если автоматический маппинг не сработал:
1. Перейдите в **Транспорт** → **Маппинг**
2. Вручную сопоставьте ID Omnicomm с госномерами

#### Шаг 4: Проверка синхронизации

1. Дождитесь первой синхронизации (до 5 минут)
2. Перейдите на **Карту автопарка**
3. Убедитесь, что ТС отображаются на карте
4. Проверьте актуальность данных (время последнего обновления)

### 3.2 Подключение СтавТРЭК

#### Шаг 1: Получение API ключа

1. Войдите в [СтавТРЭК](https://panel.stavtrack.ru)
2. Перейдите в **Настройки** → **API**
3. Создайте API ключ

#### Шаг 2: Настройка в FleetPilot

1. FleetPilot → **Интеграции** → **+ Добавить коннектор**
2. Выберите **СтавТРЭК**
3. Введите API URL и ключ
4. Подключите

### 3.3 Проверка интеграции

| Проверка | Ожидаемый результат |
|----------|---------------------|
| Все ТС отображаются | ✅ 100% ТС на карте |
| Данные актуальны | ✅ Обновление каждые 30 сек |
| Водители привязаны | ✅ Имена водителей отображаются |
| Топливо отображается | ✅ Уровень топлива виден |

## 4. Этап 2: Fuel Agent (недели 3–6)

### 4.1 Настройка базовых норм

1. Перейдите в **Настройки** → **Fuel Agent** → **Базовые нормы**
2. Введите средний расход топлива для каждого типа ТС:

| Тип ТС | Базовый расход (л/100км) |
|--------|--------------------------|
| Тягач (фургон) | 28–32 |
| Грузовик (борт) | 22–28 |
| Микроавтобус | 10–15 |
| Автобус | 16–22 |

3. Укажите коэффициенты условий:

| Условие | Коэффициент |
|---------|-------------|
| Город | 1.25 |
| Шоссе | 0.85 |
| Смешанный | 1.0 |
| Зима | 1.15 |

### 4.2 Настройка алертов

1. Перейдите в **Настройки** → **Fuel Agent** → **Алерты**
2. Настройте пороги:

| Тип алерта | Порог confidence | Действие |
|------------|------------------|----------|
| Критический слив | ≥ 0.95 | SMS + Email + Push |
| Подозрительный слив | ≥ 0.85 | Email + Push |
| Заправка вне маршрута | ≥ 0.70 | Email |
| Превышение расхода | > 20% | Дайджест |

3. Укажите получателей алертов

### 4.3 Калибровка

1. Дождитесь накопления данных за 2–4 недели
2. Проверьте базовые нормы в **Отчёты** → **Fuel Agent** → **Базовые нормы**
3. При необходимости скорректируйте коэффициенты

### 4.4 Пилотный запуск

1. Включите Fuel Agent для 5–10 ТС
2. Наблюдайте за алертами в течение 2 недель
3. Проверьте ложные алерты (should be < 8%)
4. При满意的 результатах — включите для всего автопарка

### 4.5 Ожидаемые результаты

| Метрика | Через 1 мес | Через 3 мес |
|---------|-------------|-------------|
| Расход топлива | −8–12% | −15–26% |
| Обнаружение сливов | 75% | 92% |
| Ложные алерты | < 15% | < 8% |
| Экономия/мес (30 ТС) | ₽80K | ₽142K |

## 5. Этап 3: Route Agent (недели 5–8)

### 5.1 Подключение Yandex Maps

1. Получите API ключ [Yandex Maps](https://yandex.ru/dev/maps/)
2. FleetPilot → **Интеграции** → **+ Добавить коннектор**
3. Выберите **Yandex Maps API**
4. Введите API ключ

### 5.2 Настройка ограничений

1. Перейдите в **Настройки** → **Route Agent** → **Ограничения**
2. Настройте параметры:

| Параметр | Значение по умолчанию |
|----------|----------------------|
| Макс. время вождения/день | 9 часов |
| Перерыв после | 4 часа |
| Длительность перерыва | 30 мин |
| Макс. пробег/день | 600 км |

### 5.3 Настройка временных окон

1. Перейдите в **Настройки** → **Route Agent** → **Временные окна**
2. Добавьте типичные окна доставки:

```yaml
time_windows:
  - name: "Утренняя доставка"
    start: "06:00"
    end: "10:00"
  - name: "Дневная доставка"
    start: "10:00"
    end: "18:00"
  - name: "Вечерняя доставка"
    start: "18:00"
    end: "22:00"
```

### 5.4 Тестирование

1. Создайте тестовую заявку
2. Запустите Route Agent
3. Проверьте:
   - [ ] Маршрут оптимален
   - [ ] Временные окна соблюдены
   - [ ] Топливо рассчитано корректно
   - [ ] Есть обоснование выбора

### 5.5 Пилотный запуск

1. Включите для 30% маршрутов
2. Сравните с ручными маршрутами
3. Дождитесь накопления данных за 4 недели
4. При满意的 результатах — масштабируйте

### 5.6 Ожидаемые результаты

| Метрика | Через 1 мес | Через 3 мес |
|---------|-------------|-------------|
| Пробег | −5–8% | −10–15% |
| Время в пути | −8–12% | −15–20% |
| Стоимость рейса | −6–10% | −10–16% |

## 6. Этап 4: Dispatch Agent (недели 7–10)

### 6.1 Подключение источников заявок

#### Email

1. FleetPilot → **Интеграции** → **+ Добавить коннектор**
2. Выберите **Email**
3. Настройте IMAP:
   - Сервер: `imap.list.ru` (или ваш)
   - Порт: 993
   - Email: `flash83@list.ru`
   - Пароль: [ваш пароль]
   - Интервал проверки: 60 сек

#### Excel/CSV

1. FleetPilot → **Настройки** → **Dispatch Agent** → **Импорт**
2. Загрузите шаблон Excel
3. Настройте маппинг колонок

#### Master TMS (пост-MVP)

1. Получите API ключ Master TMS
2. Настройте двустороннюю синхронизацию

### 6.2 Настройка классификации

1. Перейдите в **Настройки** → **Dispatch Agent** → **Классификация**
2. Проверьте автоматическую классификацию:

| Тип | Определение |
|-----|-------------|
| FTL | Полная загрузка, одна точка |
| LTL | Сборный груз, несколько точек |
| Срочная | Дедлайн < 24 часов |
| Критическая | Дедлайн < 4 часов |

### 6.3 Настройка назначения

1. Перейдите в **Настройки** → **Dispatch Agent** → **Назначение**
2. Настройте веса факторов:

| Фактор | Вес | Описание |
|--------|-----|----------|
| Расстояние до погрузки | 30% | Чем ближе, тем лучше |
| Опыт водителя | 25% | Знание маршрута |
| Вместимость ТС | 20% | Грузоподъёмность |
| Доступность водителя | 15% | Рабочие часы |
| Отношения с клиентом | 10% | Приоритет клиента |

### 6.4 Human-in-the-loop

**Важно:** Dispatch Agent НЕ отправляет назначения автоматически!

1. Агент предлагает top-3 варианта
2. Диспетчер просматривает и подтверждает
3. Только после подтверждения назначение отправляется водителю

### 6.5 Пилотный запуск

1. Включите для 20% входящих заявок
2. Сравните время обработки с baseline
3. Проверьте точность классификации
4. При满意的 результатах — масштабируйте

### 6.6 Ожидаемые результаты

| Метрика | Через 1 мес | Через 3 мес |
|---------|-------------|-------------|
| Время обработки | 2.8 ч → 1.2 ч | 2.8 ч → 0.4 ч |
| Точность классификации | 85% | 94% |
| Успешные назначения | 75% | 89% |

## 7. Этап 5: Maintenance Agent (недели 9–12)

1. Перейдите в **Настройки** → **Maintenance Agent** → **Интервалы**
2. Введите интервалы для ваших ТС:

| Тип ТС | Замена масла | Тормозные колодки | Шины |
|--------|--------------|-------------------|------|

1. Перейдите в **Настройки** → **Maintenance Agent** → **DTC**
2. Проверьте критические коды:

| Код | Описание | Действие |
|-----|----------|----------|
| P0300 | Пропуски зажигания | Немедленный осмотр |
| U0100 | Потеря связи с ECU | Немедленный осмотр |
| P0101 | Датчик расхода воздуха | Проверить в 3 дня |

### 7.3 Интеграция с 1С (опционально)

Если используется 1С для учёта ТО:

1. FleetPilot → **Интеграции** → **+ Добавить коннектор**

## 11. Troubleshooting

### 11.1 Проблемы с интеграцией GPS

| Проблема | Решение |
|----------|---------|
| ТС не отображаются | Проверьте API ключ, статус подписки Omnicomm |
| Данные не обновляются | Проверьте интернет-соединение, firewall |
| Неверные координаты | Проверьте маппинг ТС |

### 11.2 Проблемы с Fuel Agent

| Проблема | Решение |
|----------|---------|
| Много ложных алертов | Увеличьте confidence threshold |
| Не обнаруживает сливы | Проверьте базовые нормы |
| Нет экономии | Дождитесь накопления данных (4 недели) |

### 11.3 Проблемы с Route Agent

| Проблема | Решение |
|----------|---------|
| Маршруты не оптимальны | Проверьте API ключ Yandex Maps |
| Нарушаются временные окна | Увеличьте буфер времени |
| Высокая стоимость | Проверьте веса в настройках |

### 11.4 Проблемы с Dispatch Agent

| Проблема | Решение |
|----------|---------|
| Не парсит email | Проверьте IMAP настройки |
| Неверная классификация | Обучите модель на ваших данных |
| Нет подходящих ТС | Проверьте базу ТС и водителей |
