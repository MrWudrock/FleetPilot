## 1. Общая информация о проекте

### 1.1 Название

**FleetPilot** — B2B SaaS для управления автопарком в РФ.

### 1.2 Заказчик / стейкхолдеры

| Роль | Кто | Решение |
|------|-----|---------|
| Платит / ЛПР | Собственник / коммерческий директор транспортной компании | Go/No-go оплата после пилота |
| Пользователь-champion | Главный диспетчер, руководитель автопарка | Ежедневная работа в кабинете |
| Принимает product-решения | Product Owner / Founder FleetPilot | Scope MVP, change requests |
| Исполняет | Tech Lead + eng (API / web) | Сроки, интеграции, приёмка |

### 1.3 Задача человеческим языком

Данные автопарка размазаны по Wialon, TMS, Росдормониторингу и 1С. Диспетчер вручную сверяет заявки, габариты и топливо. Нужен **один кабинет поверх уже установленных систем**: где машины, что с заявками, нужно ли спецразрешение, где теряется топливо и сколько парк экономит в рублях.

### 1.4 Почему запускаем сейчас

- GPS/TMS уже стоят — нужен слой ценности, а не замена.
- Штрафы и негабарит давят на маржу.
- Permit API (Sprint 7) готов к пилоту.
- Founding-оффер ₽49K/мес — окно для первых клиентов.

### 1.5 Ожидаемый результат (без техники)

За 6–8 недель пилота оператор автопарка **видит живой парк на карте**, заявки из своей TMS, ускорение работы со спецразрешениями и топливными алертами, понятную экономию в ₽ — и готов платить за кабинет.

### 1.6 Пилотный клиент (референс MVP)

| Параметр | Значение |
|----------|----------|
| Автопарк | **6 ТС** |
| GPS | **Wialon Local** |
| TMS | **ТрансМенеджер** |
| Разрешения | **Росдормониторинг** |
| Учёт | **1С** (в MVP — CSV-сверка, не полный API) |

> MVP продукта = функциональность для такого пилота + демо-организация. Масштаб 20–50 ТС — после успешной приёмки (тариф Pro).

### 1.7 Сроки

| Вариант | Длительность | Итоговый дедлайн |
|---------|--------------|------------------|
| **A. Пилот на живом клиенте** (рекомендуемый) | 8 недель | Discovery 1 → Wialon/карта 2 → ТМ+Permit 2 → Fuel+ROI+1С 2 → приёмка 1 |
| **B. Продуктовое демо без live-клиента** | ~8 недель eng | Витрина продаж + stubs |

Промежуточные вехи: Flow A green (нед. 3), Flow B+C green (нед. 5), go/no-go paid (нед. 8).

## 2. Цели и задачи системы

### 2.1 Бизнес- / пользовательские цели

После внедрения должно измениться:

1. Диспетчер **не копирует** заявки и габариты между системами вручную.
2. Решение «нужно ли спецразрешение» занимает **минуты**, не часы (с утверждением человеком).
3. Руководитель видит **топливные аномалии** и **экономию ₽** в одном месте.
4. Компания готова **платить** за кабинет (North Star пилота).

### 2.2 Задачи системы (что должна делать)

1. Регистрировать организацию и пользователей с ролями.
2. Хранить карточки ТС и связывать их с unit телематики.
3. Подключать Wialon и показывать машины на карте.
4. Читать заявки из ТрансМенеджер.
5. Анализировать маршрут/габариты на необходимость спецразрешения (Permit Agent) и вести audit.
6. Считать baseline топлива и показывать алерты (Fuel Agent).
7. Показывать ROI / P&L дашборд.
8. Принимать CSV затрат из 1С для сверки.

### 2.3 Что система **не** должна делать (ограничивающий пункт)

| Не делаем в MVP | Почему |
|-----------------|--------|
| Playwright-автоматизация ЛК Росдор | Юридически чувствительно; не нужно для проверки оплаты |
| Полный API 1С / ERP | CSV уже доказывает ценность |
| ЮKassa / биллинг в пилоте | Оплата founding вручную |
| Мобильное приложение водителя | Не зарабатывает в первом пилоте |
| Enterprise ML маршрутов (OR-Tools + LLM как «чёрный ящик») | На 6 ТС нет данных; rules + HITL |
| Одновременно Omnicomm + СтавТРЭК + MSS | Пилот на Wialon |
| Автоутверждение спецразрешений без человека | HITL обязателен |
| Юридические советы «как закон» вместо ссылок на правила/реестр | Репутационный риск |

### 2.4 Приоритеты

1. **Must (M1–M10)** — без них нет пилота и оплаты.  
2. **Should** — после стабилизации Must, без срыва 8 недель.  
3. **Could** — post-pilot / второй клиент.

## 3. Целевая аудитория и сценарии использования

### 3.1 Кто пользуется

| Роль | Уровень подготовки | Контекст |
|------|--------------------|----------|
| **Admin** | IT / владелец | Онбординг, интеграции, пользователи |
| **Dispatcher** | Профессиональный диспетчер | Ежедневные заявки, карта, Permit |
| **Fleet Manager** | Руководитель автопарка | ROI, топливо, utilization |
| **Viewer** | Наблюдатель | Только чтение отчётов |

Частота: **регулярно / интенсивно** в рабочую смену (диспетчер), **регулярно** (fleet manager), **разово–еженедельно** (ЛПР смотрит ROI).

### 3.2 Типовые сценарии

#### Flow A — Activation («открыл кабинет → увидел парк»)

| Шаг | Пользователь | Ввод | Результат |
|-----|--------------|------|-----------|
| 1 | Admin | email + пароль | Вход в org |
| 2 | Admin | API-токен Wialon, маппинг 6 ТС | Интеграция Active |
| 3 | Dispatcher | открывает карту | Машины на местах со статусами |
| 4 | Fleet Manager | открывает ROI | Цифры экономии за период |

**Успех активации:** шаги 2–4 за первую неделю пилота.

#### Flow B — Заявка из ТМ → решение

| Шаг | С чем приходит | Что вводит / делает | Что получает |
|-----|----------------|---------------------|--------------|
| 1 | Новая заявка в ТрансМенеджер | — (синк) | Заявка в списке FleetPilot ≤15 мин |
| 2 | Нужно назначить / проверить ТС | Фильтры, карта | Видит availability |
| 3 | (Should) Подсказка назначения | Подтверждение suggest | Рекомендованное ТС |

#### Flow C — Негабарит → разрешение (дифференциатор)

| Шаг | Ввод | Выход |
|-----|------|-------|
| 1 | А→Б, габариты, масса, оси, госномер | `permit_required` + обоснование правил |
| 2 | Утверждение диспетчером (HITL) | Статус `approved`, audit log |
| 3 | Номер разрешения + госномер | Проверка в реестре / stub |

#### Flow D — Топливо → алерт → действие

| Шаг | Ввод | Выход |
|-----|------|-------|
| 1 | Данные топлива из Wialon | Baseline + события |
| 2 | Аномалия (слив / перерасход) | Алерт в UI |
| 3 | Разбор менеджером | Acknowledge / закрытие |

### 3.3 Нестандартные / проблемные сценарии

| Ситуация | Ожидаемое поведение |
|----------|---------------------|
| Неверный пароль / нет токена | Понятная ошибка, без утечки деталей |
| Wialon недоступен | Статус интеграции Error; кабинет жив |
| Неполные габариты в Permit | Уточняющие поля / отказ analyze с текстом «чего не хватает» |
| Нет негабарита за пилот | 5 исторических маршрутов для приёмки |
| Чужой org / чужой alert id | 403 / 404, multi-tenant изоляция |
| Плохие координаты / offline > N мин | Статус Offline на карте |

## 4. Функциональные требования

Формат Must: **задача → система → приёмка**.

### M1. Регистрация компании и вход

**Система:** signup/login email+пароль; RBAC; demo-org `demo@fleetpilot.ru`.  
**Приёмка:** signup+login; изоляция org; ошибка на неверный пароль.  
**Статус:** ✅ auth API + web.

### M2. Автопарк: карточки машин

**Система:** CRUD ТС; `external_ids` (Wialon); статусы active/inactive/maintenance.  
**Приёмка:** 6 машин; уникальный госномер в org; связь с unit.  
**Статус:** ✅ модели + seed; UI — частично.

### M3. Телематика Tier 1 (Wialon)

**Система:** token-connect; sync координат/скорости/пробега/(топлива); health.  
**Приёмка:** 6/6 unit; обновление ≤5 мин; Error без падения кабинета.  
**Статус:** 🟡 DEMO/adapter; live Wialon — P0 пилота.

### M4. Карта автопарка

**Система:** маркеры ТС; статусы движение/стоянка/offline; фильтры.  
**Приёмка:** все активные с координатами; offline помечен.  
**Статус:** 🟡 web-карта; довести под live.

### M5. Заявки из ТрансМенеджер (чтение)

**Система:** REST или XML/файл ≤15 мин; список + фильтр.  
**Приёмка:** новая заявка ≤15 мин; ошибка синка в логе.  
**Статус:** 🔴 P0 пилота (сейчас DEMO sync).

### M6. Permit Agent — анализ + HITL

**Система:** rule-based analyze; `permit_request` + audit; approve; check реестра.  
**Приёмка:** корректный `permit_required`; audit; RBAC; 5 маршрутов E2E.  
**Статус:** ✅ API; 🟡 UI; 🔴 live parser.

### M7. Fuel Agent — baseline и алерты

**Система:** baseline; алерты слив/перерасход; acknowledge.  
**Приёмка:** baseline; алерт в UI; закрытие ложного.  
**Статус:** 🟡 модели + seed; live pipeline — довести.

### M8. ROI / P&L dashboard

**Система:** экономия ₽/мес; breakdown; простая P&L (CSV/ручной ввод).  
**Приёмка:** дашборд авторизованному; цифры согласованы; скрин/экспорт.  
**Статус:** ✅ analytics API; 🟡 P&L per vehicle UI.

### M9. 1С — сверка CSV

**Система:** шаблон CSV; импорт/сверка; без полного API.  
**Приёмка:** один успешный цикл за пилот.  
**Статус:** 🔴 процесс.

### M10. Онбординг пилота (процесс)

**Система/процесс:** NDA + 152-ФЗ; kickoff; обучение 2 ч; weekly status.  
**Приёмка:** фазы 3–4 `PM-PLAYBOOK.md`.  
**Статус:** 📄 описан.

### 4.1 Подфункции Should / Could (после Must)

| Приоритет | Функция |
|-----------|---------|
| Should | История поездок, utilization, тарифные лимиты, Dispatch suggest |
| Could | Геозоны/скорость, Omnicomm, maintenance reminders |

### 4.2 Логика взаимодействия (кабинет)

Разделы UI (без пикселей): Login → Dashboard ROI → Автопарк → Карта → Заявки → Разрешения → Топливо → Интеграции → Настройки.  
Wireframes: `wireframes/index.html`, `landing/wireframes/`.

Состояния: неавторизован → сессия JWT → данные org-scoped. Смена поведения при Error интеграции — баннер статуса, не blank screen.

## 6. Требования к выходным данным

| Экран / API | Формат | Обязательно в ответе | Недопустимо |
|-------------|--------|----------------------|-------------|
| Карта | маркеры + статус | plate, lat/lon, motion | «тихий» crash |
| Список заявок | таблица | номер, А→Б, статус, ТС | чужие org |
| Permit analyze | JSON + UI-блоки | `permit_required`, правила, рекомендации | авто-approve; юридический вердикт «как адвокат» |
| Permit check | found / source | статус в реестре | полный plaintext секретов |
| Fuel alert | список | severity, title, vehicle, время | ложные без acknowledge |
| ROI | KPI cards / API | ₽ за период, breakdown | недостоверные «красивые» цифры без источника |

**Стиль UI:** деловой, русский, без маркетингового шума в операторских экранах.  
**Тональность агентов:** краткие факты + «требует проверки диспетчером».

## 7. Логика промпт-инжиниринга и агентов

FleetPilot — не один чат-бот, а **набор агентов** (шаблоны в `agents/`) + rule-engines в API. HITL обязателен для решений с юридическим/финансовым риском.

### 7.1 Роли агентов

| Агент | Назначение | MVP-режим |
|-------|------------|-----------|
| **Permit** | Анализ габаритов/маршрута, подсказки по разрешению | Rules + audit; LLM-промпты в `agents/permit-agent/` — усиление, не единственный источник истины |
| **Fuel** | Алерты слива/перерасхода | Rules + baseline; промпты для отчётов |
| **Route** | Оптимизация маршрута | DEMO / Should |
| **Dispatch** | Suggest ТС | Should |
| **Maintenance** | Напоминания ТО | Could |

### 7.2 Принципы промптов / инструкций

- Системный промпт: роль, юрисдикция РФ, запрет выдумывать номера законов / статусы реестра.
- Пользовательский: структурированный ввод (габариты, plate, А→Б).
- Скрытые: org_id, user_id, audit context — не показывать в ответе клиенту.
- Примеры (few-shot): типовые негабариты в промптах Permit.
- При неопределённости: «недостаточно данных» + список полей; **не** угадывать.
- При противоречии rule vs LLM: **побеждают детерминированные rules**; LLM — пояснение.

### 7.3 Память и состояния

- Org settings, integrations credentials (encrypted), permit_request статусы, fuel_alerts acknowledged.
- Сессия пользователя: JWT (срок ограничен); не хранить сырые пароли.
- Агент не «помнит» чужие org.

### 7.4 Защитные инструкции

- Не выдавать credentials / токены интеграций.
- Не утверждать разрешения автоматически.
- Маскировать госномер в audit (частично).
- DEMO-режимы явно помечать в UI.

## 8. Интеграции и технический контекст

### 8.1 Где используется система

| Канал | Назначение |
|-------|------------|

### 8.2 Внешние системы

|---------|-------------|-------------|----------|

| ТрансМенеджер | ← | заявки read | XML/файл ≤15 мин |
| Росдор / parser API | ←→ | rules analyze + check | DEMO stub |
| 1С | ← | CSV | Excel вручную |
| Yandex Maps / OSM | ← | карта | Leaflet tiles |
| Redis | внутр. | invites, rate limit | in-memory (dev) |
| PostgreSQL | внутр. | tenant data | — |

Credentials: encrypted at rest (`CREDENTIALS_ENCRYPTION_KEY` ≠ `SECRET_KEY`). Audit для Permit и интеграций.

### 8.3 Ограничения платформы и NFR

| Тема | Требование MVP |
|------|----------------|
| Хостинг | РФ (Yandex Cloud / Selectel / Docker on-prem) |
| Uptime | 99% пилот (не enterprise SLA) |
| Latency GPS | ≤5 мин E2E (цель 30–60 сек) |
| Безопасность | HTTPS, JWT, RBAC, bcrypt; в prod: `DEBUG=false`, `ALLOW_PUBLIC_SIGNUP=false` |
| Браузер | Chrome / Edge последние 2 версии |
| Язык UI | Русский |

## 9. Требования к качеству и оценке результата

### 9.1 Критерии «хорошего» результата

| Область | Хорошо | Плохо |
|---------|--------|-------|
| Карта | 6/6 ТС, актуальные статусы | Пустая карта без ошибки |
| Заявки | ≥70% активных из ТМ видны | Тихий рассинхрон |
| Permit | Корректный verdict на тестах; HITL; audit | Автоapprove; выдуманный закон |
| Fuel | Полезный алерт разобран | Спам ложных без закрытия |
| ROI | Цифры сверяемы с seed/пилотом | «Красивые» KPI без источника |

### 9.2 Метрики успеха пилота (приёмка → paid)

| Критерий | Порог |
|----------|-------|
| Машины на карте | 6/6, sync работает |
| Заявки из ТМ | ≥70% активных в FP |
| Permit | 5 маршрутов E2E; время −≥25% vs baseline |
| Fuel | ≥1 полезный разобранный алерт |
| ROI | дашборд за период пилота |
| WAU | 2/2 champion ≥4 недели |
| ЛПР | «готовы платить» или дата КП |

### 9.3 Допустимый уровень ошибок

- Интеграции: деградация с Error status, не downtime кабинета.
- Алерты: ложные допустимы при возможности acknowledge.
- GPS: задержка до 5 мин acceptable в MVP.

### 9.4 Как проходит приёмка

1. Чеклист Must M1–M10 + Flows A–D.  
2. Письменный go/no-go ЛПР.  
3. Change request — только с новой версией ТЗ.

## 10. Ограничения и риски

### 10.1 Юридические / этические / репутационные

- 152-ФЗ: данные в РФ, NDA на пилоте.
- Не автоматизировать вход в чужие ЛК (Playwright Росдор — вне MVP).
- Permit — инструмент поддержки, не замена юриста/логиста.
- DEMO-данные не выдавать за live клиента в продажах без пометки.

### 10.2 Чувствительные данные

- Пароли — только hash; токены интеграций — encrypted.
- JWT не логировать; plate в audit — маскировать.
- Публичный signup в prod выключен (`ALLOW_PUBLIC_SIGNUP=false`).

### 10.3 Риски и митигация

| Риск | Митигация |
|------|-----------|
| Wialon Local без внешнего доступа | VPN на неделе 1 |
| У ТМ нет REST | XML каждые 15 мин |
| Нет негабарита в период | 5 исторических маршрутов |
| Мало данных для ML | Только rules + HITL |
| Scope creep | Change request (PM Playbook) |
| Конфликт Docker web / local Next на :3000 | Один UI-процесс (RUNBOOK) |
